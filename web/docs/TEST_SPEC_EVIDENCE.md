# 테스트 사양서의 생성 기준과 원문 확인

## 어떤 자료로 생성하는가

AI 테스트케이스 생성은 선택한 **검증 실행에 고정된 요구사항 개정**을 사용한다. 최신 요구사항으로 자동 대체하지 않는다.

백엔드 `testgen/generate.py`는 소주제별로 다음 정보를 모델에 전달한다.

- 요구사항의 명세 원문(`original_text`)
- 검토 확정한 수락 조건의 키·내용·범주·정적 검증 가능 여부
- 명세 검토 메모(`review_reasons`)
- 등록되어 있는 경우 수치 제약(`constraint`)과 해석 확인 사항(`ambiguity`)

모델은 사전 조건, 시험 절차, 기대 결과, 계정·역할, 입력값, 비고와 조건 연결을 작성한다. 코드나 코드 판정을 기대 결과의 기준으로 보내지는 않는다. 코드 판정은 `adapters/v2_testgen.py`에서 별도의 **코드 기반 예측**으로 연결한다. 실제 수행의 통과·실패·보류는 사람이 기록한다.

AI가 작성한 계정·역할, 경계값, 미기재 동작 등이 모두 명세에 있다는 뜻은 아니다. 원문에 없는 가정과 생성 경고를 검토해야 한다. 이번 변경은 저장된 생성 근거를 확인하는 화면 개선이며, 모델의 생성 품질이나 추론 과정을 검증했다는 의미는 아니다.

## 화면에서 확인하는 방법

1. `저장된 사양서`에서 확인할 사양서를 선택한다. 상단의 `새 사양서 생성 기준`은 새 생성에 사용할 실행 선택이며, 열려 있는 사양서의 기준을 바꾸지 않는다.
2. 시험 목록에서 시험을 선택한다. 상세에서 사전 조건 → 시험 절차·기대 결과 → 실제 수행 기록 순서로 읽는다.
3. `요구사항·원문 보기`에서 시험 전체의 연결을 확인한다.
4. 각 단계의 `이 단계의 근거`에서 그 단계에 연결된 수락 조건만 확인한다.
5. 창에 표시된 요구사항 개정, 조건 내용, 원문 인용을 비교한다. `PDF N쪽 원문 열기`로 문서의 해당 쪽을 연다.

조건별 원문 인용이 없으면 요구사항 수준의 인용임을 명시한다. 인용·쪽수·조건·요구사항 개정을 찾지 못하면 누락 상태를 표시한다. 다른 조건이나 최신 개정으로 대신 채우지 않는다. 수동 시험의 연결은 사용자가 지정한 참고 명세이며, AI 생성 근거와 구분해 표시한다.

근거 창을 열고 닫아도 편집 초안은 유지한다. Escape 또는 닫기 후 열었던 버튼으로 키보드 포커스가 돌아간다. 사전 조건도 시험 편집에서 수정할 수 있으며, 기존 일괄 저장 API를 사용한다.

## 사용하는 기존 API

| 목적 | API 및 필드 |
| --- | --- |
| 사양서에 고정된 개정 | `GET /api/v2/projects/{p}/test-specifications/{s}`의 `requirement_versions` |
| 시험·단계별 연결 | `GET /api/v2/projects/{p}/test-cases?test_specification_id={s}`의 `requirement_links`: `requirement_id`, `requirement_revision`, `condition_ids` |
| 해당 개정의 조건·출처 | `GET /api/v2/projects/{p}/requirements/{r}?revision={n}`의 `conditions`, `source_refs`, `location.index` |
| 문서 이름 | `GET /api/v2/projects/{p}/documents/{d}`의 `filename` |
| PDF 원문 | `GET /api/v2/projects/{p}/documents/{d}/file#page={n}` |

별도의 API 계약 변경은 없다. 연결된 요구사항 일부 조회가 실패해도 시험 내용은 표시하고, 해당 근거를 불러오지 못했음을 안내한다.

## 검증 기록 — 2026-10-30

- 최신 main 반영: 프론트엔드 `e122fe2`, 백엔드 `f6a71d3`.
- 기존 로컬 화면 변경을 보존하고 기능 브랜치 `feat/test-spec-readability`에서 작업했다.
- `cd web && npm run build`, `cd web && npm run lint` 통과. 기존 번들 크기 경고는 유지된다.
- Node 22 이상: `node --experimental-strip-types --test web/tests/testEvidence.test.mjs` 통과. 고정 개정, 연결 중복, 누락 조건, 조건별 인용과 요구사항 인용의 구분을 검사한다.
- 별도 로컬 점검 DB에 저장된 AI 생성 시험 3개로 목록 선택, 긴 제목, 코드 예측·가정 펼침, 시험 전체·단계별 근거, 원문 인용, PDF 해당 쪽 열기를 확인했다.
- 사전 조건 임시 편집 → 단계 근거 열기·닫기 → 초안 유지 → 취소 후 복원과 키보드 포커스 복귀를 확인했다. 저장된 시험과 실제 수행 기록은 이 점검에서 변경하지 않았다.
- 넓은 화면의 목록·상세 배치와 좁은 화면의 세로 배치를 점검했다. 상단 선택 항목·버튼이 줄바꿈되어 가로 넘침을 만들지 않도록 수정했다.
- 이번 점검은 기존 생성 데이터를 재사용했으며, 추가 유료 LLM 호출을 하지 않았다.
