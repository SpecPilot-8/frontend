# 테스트 사양서의 설계 근거 확인

갱신일: 2026-10-30

## 요구사항과 시험을 나란히 검토하기

시험 상세 오른쪽의 ‘요구사항·수락 조건 대조’에서 고정 개정의 원문 전체와 모든 수락 조건을 확인한다. 작은 화면에서는 아래에 이어서 표시한다. 선택 시험이 일부 조건만 담당하더라도 다른 조건을 숨기지 않고 다른 시험 연결·미연결을 구분한다. ‘사양서 전체’와 검색으로 전체 범위를 확인한다.

각 조건에 해당 단계·기대 결과·AI 설명을 표시하고, 단계 이동과 PDF 원문 확인을 제공한다. 조건별 ‘설계 적합성 검토’에서 설계 적합·보완 필요·판단 보류와 사유를 저장한다. 저장은 별도의 사람 판단 기록이며 실제 시험을 수행했다고 기록하지 않는다. 시험 절차 개정이 바뀌면 새 개정은 미검토이고, 이전 검토는 서버에 보존된다. 편집 중에는 설계 검토 저장을 막고 새 절차를 먼저 저장하도록 안내한다.

연결 수는 시험의 의미적 충분성이나 실제 통과율이 아니다. 사용자는 명세 원문·준비 상태·입력값·관찰 가능한 기대 결과·필요한 경계/오류/권한 조합을 대조한다. ‘시험 생성 방식과 검토 기준’에서 LLM에 전달되는 명세와 코드 예측/실제 수행의 차이를 설명한다.

검증 명령에 `node --experimental-strip-types --test tests/testComparison.test.mjs`를 추가한다. 조건 전체 유지, 다른 시험·미연결, 다른 개정 거부, 편집 초안 대응과 충분성 미추정을 검사한다. 조건별 저장·재진입, 절차 보완 후 미검토, 원문/단계 이동은 분리 DB에서 확인한다.

## 사용자 흐름

1. **AI 테스트케이스 생성**을 누르면 바로 모델을 호출하지 않고 설계 계획을 연다. 서버 모델, 고정 명세 개정, 조건별 권장 시험 관점과 선정 기준을 검토한다. 원문을 열어 확인하거나 취소할 수 있다.
2. 새로 생성한 사양서의 시험 상세에서 시험 목적을 읽는다. 각 단계는 절차·명세 기대 결과 → 입력값/역할 → 선정 이유 → 명세 조건/원문 인용 → 실제 수행 순서로 표시한다.
3. **이 단계의 근거** 또는 **요구사항·원문 보기**에서 전체 조건과 인용·PDF 페이지를 확인한다. 최신 요구사항으로 조용히 바꾸지 않고 사양서에 고정된 개정을 조회한다.
4. **시험 설계 점검**의 요약과 점검 항목을 통해 연결되지 않은 관점·해석 확인이 필요한 시험을 찾아 원문 또는 시험으로 이동한다. 검색·필터·추가 보기를 제공한다.
5. 시험을 편집하면 이전 AI 설명에 재검토 표시가 붙는다. 저장하지 않은 편집은 점검 집계에 반영하지 않으며 취소하면 이전 상태로 돌아간다. 실제 수행 기록은 별도다.

## 신뢰 범위

- 관점 선정은 서버 규칙의 제안, 설계 이유는 AI가 작성한 설명이다. 둘 다 시험 적합성의 보증이 아니므로 원문과 대조한다.
- ‘시험 연결됨’은 저장된 연결 기록을 뜻한다. 실제 시험 통과·업무 전체 커버리지로 표현하지 않는다.
- 이전 사양서는 작성 당시 이유와 계획이 없으면 미기록으로 표시한다. 수동 시험을 AI가 설계했다고 표시하거나 예전 생성 이유를 추정하지 않는다.
- 계획 조회 실패는 빈 점검으로 표시하지 않고 재조회 안내를 제공한다. 사양서 이동 중 이전 사양서의 근거를 보여주지 않는다.
- 기존 색상·카드·표·대화상자 디자인을 사용한다. 추가 정보는 상단 요약과 단계별 근거로 나누고 긴 점검 목록은 기본 접힘 상태로 둔다.

## 확인 방법

`npm run build`, `npm run lint`, `node --experimental-strip-types --test tests/testEvidence.test.mjs`.

분리된 점검 DB와 가짜 모델 응답으로 새 사양서의 이유/입력값/원문, 미포함·검토 관점, 기존 자료의 미기록 안내, 편집/취소, 생성 전 계획/원문/취소, 900px·1280px 표시를 확인한다. 실제 모델 출력의 설명 품질은 실제 기획서를 이용해 별도 평가한다. 기존 사양서에는 새 생성 이유가 소급 추가되지 않는다.
